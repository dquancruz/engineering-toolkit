# Oncall Ticket Creator

Reads the JSON report generated by `jira-defects-report` and produces a formatted Markdown oncall story ticket with all active defects ordered by priority.

---

## Prerequisites

- Node.js v18 or higher
- A JSON report generated by `jira-defects-report`

---

## Installation

No extra dependencies needed. Uses the shared `node_modules` from the parent `tools/` folder.

```bash
cd tools
npm ci
cd oncall-ticket-creator
```

---

## Usage

```bash
npm start -- <path-to-report.json> ["Oncall Name"] ["Sprint Name"]
```

**Arguments:**

| Argument | Required | Description |
|---|---|---|
| `path-to-report.json` | Yes | Path to the full report JSON from `jira-defects-report` |
| `"Oncall Name"` | No | Name of the oncall engineer (default: `Oncall Engineer`) |
| `"Sprint Name"` | No | Sprint label (default: `Current Sprint`) |

**Examples:**

```bash
# Minimal — just the report
npm start -- ../jira-defects-report/reports/report_Jira_2026-05-13T19-06-42.json

# With oncall name
npm start -- ../jira-defects-report/reports/report_Jira_2026-05-13T19-06-42.json "Daniel Quan"

# With oncall name and sprint
npm start -- ../jira-defects-report/reports/report_Jira_2026-05-13T19-06-42.json "Daniel Quan" "Sprint 42"
```

`npm start` compiles the TypeScript first, so no compiled `.js` is kept in the repo.

---

## Output

The ticket is printed to the console and saved as a `.md` file inside the `./tickets/` folder:

```
tickets/oncall_Daniel_Quan_2026-05-13T19-17-23.md
```

### Ticket structure

```markdown
# Oncall Story — Active Defects Tracker

| | |
|---|---|
| **Date** | Wednesday, May 13, 2026 |
| **Oncall** | Daniel Quan |
| **Sprint** | Sprint 42 |
| **Source report** | Jira.csv |
| **Total defects** | 26 |

## Priority Breakdown

| Priority | Count |
|---|---|
| Blocker | 1 |
| Highest | 7 |
| High | 2 |
| Medium | 16 |

## Status Breakdown

| Status | Count |
|---|---|
| In Progress | 15 |
| DRAFT | 4 |
| To Do | 4 |
| Blocked | 2 |
| Review In Progress | 1 |

## Defects — Ordered by Priority

| # | Key | Priority | Status | Summary | Assignee | Reporter | Last Updated |
|---|---|---|---|---|---|---|---|
| 1 | [PROJ-101](...) | Blocker | In Progress | Service crashes on startup... | Jane Doe | Jane Doe | April 20, 2026 at 11:02 AM |
| 2 | [PROJ-102](...) | Highest | In Progress | [Onboarding] Device discovery fails | Jane Doe | Daniel Quan | April 20, 2026 at 11:01 AM |
| ...

## Oncall Actions

- [ ] Review all Blocker / Highest defects
- [ ] Confirm assignees are actively working on blockers
- [ ] Update statuses in Jira
- [ ] Escalate any unassigned high-priority defects
- [ ] Add notes / comments to blocked items

---

*Generated by oncall-ticket-creator on 2026-05-13T19:17:23.035Z*
```

---

## Priority order

Defects are sorted from most to least critical:

1. Blocker
2. Highest
3. High
4. Medium
5. Low

---

## Typical workflow

```bash
# 1. Generate the defects report from a Jira CSV
cd jira-defects-report
JIRA_BASE_URL=https://your-company.atlassian.net npm start -- csv/Jira.csv

# 2. Create the oncall ticket from the generated report
cd ../oncall-ticket-creator
npm start -- ../jira-defects-report/reports/report_Jira_<timestamp>.json "Your Name" "Sprint XX"
```
